# Catalogue meshes and search vectors

What a deploy cannot carry and a seeder cannot make.

`DemoCatalogSeeder` creates the thirty-one listings and ships their photographs beside it, so
a fresh server gets a shop with products in it. Two things are missing from that shop and
both cost money to produce: the 3D model of each product, generated one call at a time, and
its search vector, generated by an embedding call. Making them again on every new server is
paying twice for the same answer, so they are in here instead.

Written by `refconcept:export-catalogue --only=model_3d`, read by
`refconcept:import-catalogue`. Keyed by product slug rather than by id, because the seeder
mints fresh ids on an empty database and an export keyed by id restores nothing while
reporting success.

## On a new server

```
php artisan db:seed --class=DemoCatalogSeeder     # the listings and their photographs
php artisan refconcept:import-catalogue database/catalogue
```

Safe to run twice: media is matched on its type and original name, vectors on their content
hash, and anything already there is left alone. `--pretend` says what it would do.

## Refreshing this

When the catalogue changes, export again from the machine that has the meshes:

```
php artisan refconcept:export-catalogue --only=model_3d --out=database/catalogue
```

The photographs deliberately stay out of it — they are already in the repository under
`database/seeders/assets/products`, and carrying them here as well is two and a half
megabytes of the same pictures.
